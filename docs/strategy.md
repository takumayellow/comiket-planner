# コミケ巡回の戦略メモ（C108 1日目・土曜想定）

このドキュメントは「どの順で回るか」の前段——**どこに人気が集中し、いつ並び、どのホールに
最初に入るか**——を整理する。巡回順そのものは `comiket_planner` が計算するが、その *開始点*
は入場チケットで決まるため、まずそこを固める。

> 注意: 待機列の細かい時刻・入場方式は毎回サークルカット/開催情報で更新される。ここは一般則
> なので、**最終的な集合時刻・リストバンド運用は公式の「開催情報」「アピール」で必ず確認**すること。

## 2. 入場方式：ホールは「選べる」とは限らない

現行コミケはリストバンド型参加証（事前販売、時間帯別）。ざっくり:

- **アーリー入場**: 最も早く入れる枠。**購入時に「東地区」か「西南地区」かに分かれている**。
  → 買った時点で **最初に入るホールが確定**する（当日は選べない）。
- **午前入場リストバンド**: 地区分けなし。当日、東 or 西の待機列のどちらかへ案内される
  （日により運用が違う）。アーリーより後に入場。
- **午後入場**: 13時以降。大手はほぼ完売済み。島の残りと在庫拾い向き。

つまり **「どの間から回るか」は自分で自由に決められない**。アーリーなら購入地区で、
午前なら当日の案内で、最初のホールが決まる。だから巡回計画は
**「入るホール別に3パターン」用意**しておくのが正しい（`route.md` の比較表がこれ）。

## 5. 巡回順の作り方（このツールが自動化する部分）

`comiket_planner` は上の初動（開始ホール）を入力に、次を最適化する:

1. **完売減衰**: 到着が遅いほどサークルの価値が下がる。優先度が高い/壁ほど減衰を急にして
   早い時間に寄せる。
2. **島内の拾い方**: 島ブロックに着いたら、その島の連番（下側の番号）は歩いて拾う前提。
   代表番号だけで棟内の巡回順を組み、細かい番号は現地で消化する。
3. **棟間移動の最小化**: 東7⇄西のような高コスト移動を減らす順序に 2-opt で整える。
4. **時間予算**: 使える時間を指定すると、報酬密度の低い（優先度低・並び長い）サークルから
   自動で落として、回り切れる範囲に収める。

→ 実際の順は `route.md`（個人用）/ `python -m comiket_planner.cli` で出力。
